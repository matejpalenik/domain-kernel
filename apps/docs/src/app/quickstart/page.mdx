# Publish a reviewed recruitment model

Set up the SDK, publish a manually reviewed domain model, and read its two
released versions in a separate Python process.

## Install from source

You need Python 3.13 or newer, Git and uv 0.13.7 or newer. Run these commands in a
terminal. Node and pnpm are not required to use the Python SDK.

<CodeGroup>

```sh
git clone https://github.com/matejpalenik/domain-kernel.git
cd domain-kernel
uv sync --locked --no-dev
```

</CodeGroup>

The checkout installs the core package using the committed dependency lockfile.
Optional adapters and notebook tooling are separate from the core runtime.

## Review, publish, and share

Run the sample from the repository root.

<CodeGroup>

```sh
uv run --locked --no-dev python -m examples.recruitment_quickstart
```

</CodeGroup>

The sample uses the recorded digest for the original English AI Act edition and
creates a temporary SQLite workspace. A scripted reviewer examines the vocabulary
and relationships, then a sample publisher releases the inspected snapshot.
The reviewed correction changes the purpose limit from two to three.
The consumer opens both JSON files and prints each version and purpose limit.

Open the [developer tour](/tour) to follow a source passage through discovery,
review, and publication in a notebook.

## Create a typed diagnostic

Save this as `first_contract.py` in the repository root:

<CodeGroup>

```python
from domain_kernel import Issue, IssueSeverity, ProjectId

project_id = ProjectId(value="project-recruitment-policy")
issue = Issue(
    code="missing-evidence",
    path=["definitions", 0, "meaning"],
    message="Attach a source passage before accepting this meaning.",
    severity=IssueSeverity.WARNING,
)

print(project_id.value)
print(issue.code, issue.severity.value)
print(issue.message)
```

</CodeGroup>

Run it from the same directory:

<CodeGroup>

```sh
uv run --locked --no-dev python first_contract.py
```

</CodeGroup>

You will see the identifier, `missing-evidence warning`, and the diagnostic
message. The identifier wraps a supplied value; this example does not persist a
project. `Issue` validates its fields and keeps an immutable copy of its path.

## Understand validation

The foundation objects reject invalid values at construction. An empty identifier,
for example, raises `ValueError`. Catch errors where your application can explain
them or ask for a correction.

<CodeGroup>

```python
from domain_kernel import ProjectId

try:
    ProjectId(value="")
except ValueError as error:
    print(error)
```

</CodeGroup>

The [reference](/reference) describes the implemented exports.
